# 从参考图片 / Excel 提取样式

用户说不清想要什么样式，但几乎都能拿出一张"我喜欢这个"的截图，或一份品牌规范。
`style` 命令把参考文件变成一套设计规范，排版引擎必须照着执行。只在提示词里写"参考这张图的风格"是建议，模型可以无视；规范里的数值不行。

```bash
python3 scripts/deckforge_cli.py style <文件> --styles <工作目录>/styles [--base exec-brief] [--name acme]
```

## 能取到什么

| 参考文件 | 取到的 | 取不到的 |
|---|---|---|
| 幻灯片截图（16:9） | 背景色、文字色、强调色、左右页边距 | 字体、字号 |
| 海报、logo、非 16:9 图片 | 背景色、文字色、强调色 | 页边距、字体、字号 |
| 品牌规范 Excel | 各角色颜色、标题字体与正文字体 | 字号 |
| 普通 Excel（无规范表） | 强调色（表头填充色或自定义主题）、文字色、主题字体 | 背景色等 |

Excel 规范表能识别这些写法（标签在左，值在右）：

- `品牌主色 | #C8102E`、`背景色 | RGB(255,255,255)`、`正文颜色 | 333333`
- `辅助色 | (一个填了颜色的空单元格)`
- `标题字体 | 思源黑体 Heavy`、`正文字体 | 思源黑体`

识别的角色关键词：主色/品牌/强调/accent/primary → 强调色；背景/底色 → 背景；标题/文字/text → 主文字；正文/body → 正文；辅助/次要/灰/secondary → 弱化文字；分隔/边框/线条 → 分隔线。

**字号层级不从参考里取。** 它继承自基础规范（`--base`；不填时浅色背景用 editorial-report，深色背景用 technical-deck）。层级比例是专业感的主要来源，从一张截图反推字号误差太大，不如保住一套校准过的阶梯。`--base` 按场景选，规则和不用参考时一样。

## 返回结果，以及要告诉用户什么

```json
{
 "name": "ref-brand",
 "based_on": "technical-deck",
 "colors": {"bg": "#0F1B2D", "accent": "#0065D7", ...},
 "from_file": {"accent": "brand!B1「品牌主色」", ...},
 "adjustments": ["accent #0057B8 在背景 #0F1B2D 上对比度只有 2.5，已调整为 #0065D7（≥ 3.0）"],
 "notes": ["字体「思源黑体」需要在打开 PPT 的电脑上已安装…"]
}
```

用一两句话告诉用户：

1. 用了参考里的哪些东西（`from_file`），哪些沿用基础规范（`inherited`）
2. **每一条 `adjustments`**。为保证可读，颜色会按角色调到最低对比度（主文字 7，正文 4.5，强调色和弱化文字 3）。品牌色被改了却不说，用户会以为取错了色。如果用户坚持要用原色，可以手动改规范 JSON（见 `contracts.md`），但要说明小字可能看不清
3. `notes` 里的提醒：截图取色是近似值；品牌字体需要对方电脑上已安装

## 常见情况

- **截图取色不准**：小字号的强调色被抗锯齿冲淡，取到的颜色会偏浅一点。用户要精确品牌色时，请对方给色值，或者直接按 `contracts.md` 手写规范
- **用户直接在对话里给了色值**（"主色 #C8102E，背景白色"）：不必走 `style`，按 `contracts.md` 复制一份基础规范改 colors 即可
- **照片或渐变背景**：notes 会提示"背景不是纯色"。背景色仅供参考，最好和用户确认
- **Excel 是数据不是样式**：它是内容来源。读数据写进 deck.json，不要提取样式。分不清时问一句
- **.xls / .pptx / .pdf**：`style` 不支持。.xls 请用户另存为 .xlsx；PPTX 或 PDF 参考稿可以先转成图片（如 `soffice --headless --convert-to pdf` 再 `pdftoppm -png -f 2 -l 2`），挑一页有代表性的内容页（不要用封面）作为截图参考
- **多个参考文件**：Excel 规范的颜色和字体更准，优先用它。截图只用来补 Excel 没给的项（比如页边距），这需要按 `contracts.md` 手工合并
